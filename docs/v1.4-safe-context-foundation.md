# NKCrane v1.4.0 — Safe context foundation

**Status:** preview pull request; no RunningBoard hook, no daemon injection, and no automatic respring added.

## Scope implemented

- Fix destructive paths in NKCStore: never derive a delete target with stringByDeletingLastPathComponent from a virtual root. Resolve <real App sandbox>/Library/__NKCrane_Containers/<lowercase UUID> explicitly.
- Reject malformed UUIDs, symlinks in managed path ancestors, dangling/redirected legacy Root links, unmigrated legacy Root directories and operations on the currently selected container.
- Wipe only children of that validated named root, preserving its parent and all sibling containers. Return filesystem errors rather than reporting unconditional success.
- Add bounded portable parser for \`NKCRANE_LAUNCH_CONTAINER_ID\` with statuses \`NAMED\`, \`DEFAULT\`, \`ABSENT\`, \`INVALID\`, \`UNKNOWN\`. An absent marker means **no launch context evidence**, not Default.
- Add read-only \`nkcraneprobe\` diagnostics using \`KERN_PROCARGS2\` to inspect launch capsules for running PIDs. At this stage the existing v1.3.2 app runtime does not generate that pre-spawn marker, so \`ABSENT\` is expected and **not** an error.

## Test on a jailbroken iPhone

1. Install the PR workflow artifact on a test device only (do not replace your stable release).
2. Run \`nkcraneprobe com.facebook.Facebook\` and review \`process_launch_capsules\`, \`loader_truth\`, and \`physical_runtime\`.
3. In a disposable test app, create container A and B. Switch away from A, then wipe A. Verify B's \`Documents\` and \`Library\` remain byte-for-byte unchanged.
4. Try deleting/wiping an active container: it must be rejected with code 409.
5. Test a container created by an older version but not yet opened/migrated: deletion and wipe must be rejected, not silently remove its parent.
6. Reinstall 1.3.2 if startup behavior differs; the new parser is not hooked into app runtime.

## Not implemented in this phase

- RunningBoard \`RBProcessManager\` interception.
- Authoritative PID/start-time context attestation, XPC helper, MCM/CFPrefs/securityd interception.
- Atomic wipe/rollback journal, app-family process termination orchestration.
- Claims that Facebook A/B are fully isolated.

## Safety limitations

This change prevents broad parent-directory deletion but does not provide a crash-safe atomic transaction: filesystem deletion can partially complete if interrupted. Destructive operations should therefore only be used after backing up and while the target app and its extensions are stopped. Legacy data should be migrated by launching the named container once before wipe/delete.

No proprietary Crane binaries or decompiled code are copied. Code is a separate implementation.
