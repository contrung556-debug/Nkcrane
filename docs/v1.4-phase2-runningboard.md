# NKCrane v1.4 — Phase 2: experimental RunningBoard capsule

## Status

Experimental code only. Normal builds do not compile or package NKCraneRB;
they retain compatibility with v1.3.2 runtime routing when pre-spawn markers
are absent.

Developer-only opt-in build:

    make clean package FINALPACKAGE=1 NKC_EXPERIMENTAL_RB=1

This build includes NKCraneRB.dylib + NKCraneRB.plist filtered solely to
runningboardd. Installing it modifies a critical system process; use an
isolated test iPhone with recovery access. It is NOT uploaded to Sileo.

## New flow

    nkcranectl set-active / registry mirror synchronized
           |
           v
    Public registry.json (atomic rename publication)
           |
           v
    NKCraneRB in runningboardd (experimental only)
           |
           v
    RBProcessManager request.context
           |
           | _additionalEnvironment copy
           | _setAdditionalEnvironment:
           v
    NKCRANE_LAUNCH_CONTAINER_ID=<UUID | DEFAULT>
           |
           v
    App-side immutable NKCProcessLaunchCapsule snapshot
           |
           v
    NKCRegistryAdapter chooses per-PID context
           |
           v
    Existing NKCInAppLayout / NKCSafeRuntime / Tweak.xm

The registry represents NEXT launch; explicit capsule represents CURRENT
process. Absent marker preserves the previous registry-based behavior.
The marker is a launch-context hint, not cryptographic attestation.

## Compatibility rules

- Never modify Apple/system bundle IDs.
- If registry cannot be read, skip all RB launch hooks.
- Missing request, context, selectors, invalid bundle or UUID: forward original
  Apple launch request unchanged.
- Preserve existing environment keys; do not overwrite an existing capsule.
- Hook only when method argument count and return signature match wrapper.
- Explicit DEFAULT is different from ABSENT/INVALID/UNKNOWN.

## Known limitations

1. Private RBProcessManager APIs may differ. Compilation cannot prove hooks
   installed on a particular iOS release.
2. Registry read requires appropriate sandbox/libSandy permissions.
3. No authoritative audit-token or process-start-time verification yet.
4. Existing app-side preferences/keychain/App Group isolation remains partial.
5. A capsule alone is NOT proof that a named container is fully isolated.
6. Developer-only RB injection can destabilize runningboardd; never
   distribute the opt-in package as stable.

## Test-device verification

1. Confirm standard artifact excludes NKCraneRB.dylib and NKCraneRB.plist.
2. Run named A, named B, Default in a disposable app.
3. On experimental build, check RB hook logs and nkcraneprobe
   process_launch_capsules / loader_truth / physical_runtime fields.
4. Switch NEXT active selection while an old PID remains alive; old PID must
   retain old context and new PID should get new context.
5. Missing registry and unknown bundles must launch without modification.
6. Roll back to standard build if startup becomes unstable.

CI on this branch also verifies the ordinary package excludes the RB injection payload and compiles the opt-in developer variant separately. Passing CI is not the same as verifying runtime behavior on a jailbroken iPhone.

Independent implementation; no proprietary Crane code copied.
